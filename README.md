# VIVER AR

Android Chrome에서 손목에 시계를 착용해 보는 전체 화면 웹 프로토타입입니다.

1. 카메라 시작을 누르고 카메라 권한을 허용합니다.
2. 손등과 손가락을 화면에 담고 약 2초간 멈춥니다.
3. 방향을 다시 맞추려면 오른쪽 아래 **손등 재추적**을 누릅니다.
4. 옆의 **카메라 전환**을 누르면 전면·후면을 바꿉니다. 전환 뒤에는 손등을 보여 새 기준을 잡습니다.

착용 중에는 카메라와 시계, 재추적·카메라 전환 버튼을 표시합니다. 손을 잃으면 복귀 안내를 표시합니다. 손이 화면에서 0.8초 이상 사라졌다가 하나만 돌아오고 기존 추적이 0.6초 동안 복구되지 않으면 자동으로 새 기준을 잡습니다. 새 기준도 손등과 손가락을 편 안정된 관측 약 1.5초가 필요합니다. 짧은 가림이나 정상 복귀에는 기존 기준을 유지합니다. 전체 화면을 지원하지 않으면 웹페이지 영역을 채웁니다. 다른 앱으로 이동하면 카메라를 종료하며, 돌아온 뒤 다시 시작할 수 있습니다.

카메라 영상은 기기에서 처리합니다. 서버로 영상이나 관절 좌표를 전송하지 않으며 진단 기록도 자동으로 시작하지 않습니다. 단일 카메라의 추정이므로 빠른 회전·가림·손목 꺾임에는 오차가 남을 수 있습니다.

## 0.7.19 실제 시계 테스터 배포

bluewhale127 개발 사이트에서 검증한 Datejust GLB, 100% 기본 크기, 완화된 금속 조명, 기존 원기둥 가림을 공유 화면에 적용합니다. 모델은 페이지에서 자동으로 준비하며 다운로드가 끝난 뒤 카메라를 시작할 수 있습니다. 다운로드나 GLB 열기에 실패하면 오류와 다시 불러오기 버튼을 표시합니다.

전체 화면 카메라, 손등 재추적·카메라 전환 버튼, 카메라 원본 기준 첫 인식 및 손 복귀 자동 재추적은 0.7.15의 동작을 유지합니다. 개발 화면을 공유 화면으로 교체하는 빌드 방식도 유지합니다. 시계 모델은 약 22MB이고 고정 브레이슬릿이며, 실제 손목 단면에 자동 변형하지 않습니다. 원기둥과 실제 팔이 맞지 않으면 비침이나 위치 오차가 남을 수 있습니다.

검증: 자동 검사 117개 및 공유 빌드 통과. 휴대폰 세로 화면의 통제된 카메라 입력에서 실제 GLB 연결, 전면·후면 전환, 손 복귀 자동 재추적과 수동 재추적을 확인했습니다. 모델 다운로드 실패와 잘못된 GLB 응답의 재시도도 확인합니다. 이는 실제 Android 카메라의 정확도나 성능 측정은 아닙니다.

## 개발

Node.js 20 이상에서 실행합니다.

```sh
npm ci
npm test
npm run build:share
```

배포 결과는 `dist-share/`입니다. `npm start`는 설정이 포함된 개발 화면을 열고 `/share.html`에서 공유 화면을 확인할 수 있습니다. GitHub Actions는 테스트 후 공유 화면을 GitHub Pages로 배포합니다.

버전 0.7.15. 공유 화면에 카메라 전환과 손 복귀 시 자동 기준 재설정을 추가했습니다. 회전 보정과 시계 모델은 유지합니다. 자동 검사 108개를 통과했습니다. 통제된 브라우저 입력으로 손이 사라진 뒤 다른 위치·크기로 돌아오는 경우를 재생하여, 0.7.14의 복귀 실패와 수정 후 전면·후면 모두 약 2.5초 만의 복귀를 확인했습니다. 이전 엔진에도 같은 실패 조건이 있으며 이 검사는 특정 휴대폰에서 두 주소의 체감 차이가 난 원인을 확정하지 않습니다. 실제 Android 카메라 성능과 추적 정확도를 보장하는 검사는 아닙니다.
